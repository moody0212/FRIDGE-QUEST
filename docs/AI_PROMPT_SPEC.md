## 1. 프롬프트 핵심 비즈니스 규칙 (7대 레시피 품질 규칙)

1. **입력 재료의 성격 판단 (내부 분류)**:
   - 레시피를 만들기 전 입력 항목을 생식재료(양파, 삼겹살 등), 일반재료(계란, 두부 등), 조리식품(김치 등), 이미 완성된 음식(파프리카감자샐러드, 남은 치킨 등)으로 내부 판단한다.
2. **모든 냉털 재료 억지 사용 금지**:
   - 🟡(시들거나 물러짐) 재료를 최우선으로 쓰되, 궁합이 어울리는 재료만 활용한다. 맛이나 조리 방식이 어울리지 않는 재료는 과감히 제외한다.
3. **완성된 음식 별도 처리**:
   - 이미 조리/완성된 음식은 생식재료처럼 세척, 손질, 볶기 등의 과정을 일괄 적용하지 않는다.
   - 곁들여 먹기, 토핑, 소스 등으로 안내하고 필요 시 `tip` 필드로 제공한다.
4. **재료별 적절한 조리 동작 사용**:
   - 모든 재료에 "손질하여 볶는다" 식의 동일 문장을 일괄 적용하지 않고, 양파(썰기), 삼겹살(자르기), 계란(풀기) 등 구체적 동작을 서술한다.
5. **한국어 조사 자연스럽게 처리 (괄호 금지)**:
   - 레시피 출력 문장에 `(을/를)`, `(이/가)`, `(은/는)` 과 같은 괄호형 조사를 절대 표시하지 않으며 한국어 받침에 맞는 조사를 적용한다.
6. **실제 식사 가능한 레시피 우선**:
   - 요리 상식상 실제로 맛있게 만들 수 있는 레시피를 우선 추천한다.
7. **출력 데이터 일치성 (정합성)**:
   - `rescueUsed`: 메인 조리법에서 실제 사용된 냉털 재료만 포함 (미사용/곁들임 제외).
   - `basicUsed`: 체크한 기본 재료 중 실제 사용된 재료만 포함.
   - `extraNeeded`: 꼭 필요한 추가 필요 재료만 포함.
   - 조리법에 등장하는 모든 재료는 위 재료 목록에 100% 존재해야 함.

## 2. 입출력 스키마 (TypeScript & JSON)

### 2.1 Request Payload
```typescript
export interface QuestApiRequest {
  basics: string[]; // 사용자가 체크한 기본 재료 목록 (예: ["김치", "대파", "간장"])
  items: {
    name: string;   // 냉털 식재료명 (예: "양파", "엄마가 만든 파프리카감자샐러드")
    status: 'fresh' | 'soft' | 'bad'; // 상태
  }[];
  cookTime: '10' | '20' | 'any'; // 조리 가능 시간
  excludeDish?: string; // 다른 요리 추천(Reroll) 시 제외할 이전 요리명
}
```

### 2.2 Response Payload (Structured JSON Output)
```typescript
export interface QuestApiResponse {
  rescueTarget: string;      // 구조 대상 재료명 (예: "양파")
  dish: string;              // 추천 요리명 (예: "삼겹살 양파볶음")
  time: string;              // 예상 조리시간 (예: "약 15분")
  rescueUsed: string[];      // 실제 사용된 냉털 재료 목록
  basicUsed: string[];       // 실제 사용된 기본 재료 목록
  extraNeeded: string[];     // 추가 필요 재료 목록 (없으면 [])
  steps: string[];           // 최대 5단계 조리법 문자열 배열 (1~5개)
  tip?: string;              // 완성된 음식의 곁들임 팁 또는 조리 팁 (선택)
  warningMessage?: string;   // 🔴 재료 관련 안전 경고 문구 (필요시)
  exp: number;               // 보상 경험치 (80 ~ 150)
}
```

## 3. 시스템 프롬프트 템플릿 (System Prompt)

```markdown
당신은 냉장고 식재료 구조 퀘스트 마스터 AI입니다. 사용자가 입력한 냉장고 재료를 분석하여 실제로 만들 수 있는 맛있는 요리 1개를 추천하고 JSON으로 응답하세요.

[입력 데이터]
- 보유 기본 재료: ...
- 냉털 재료(시들거나 물러짐 🟡): ...
- 냉털 재료(상태 많이 안 좋음 🔴): ...
- 냉털 재료(신선함 🟢): ...
- 조리 가능 시간: ...
- 제외할 이전 요리명: ...

[핵심 레시피 생성 필수 규칙]
1. [재료 성격 판단] 입력된 재료를 생식재료(양파, 삼겹살), 일반재료(계란, 두부), 조리식품(김치), 이미 완성/조리된 음식(샐러드, 남은 치킨 등)으로 구분하여 레시피에 적용하세요.
2. [모든 재료 억지 사용 금지] 입력된 모든 냉털 재료를 한 요리에 억지로 다 넣지 마세요. 🟡 상태 재료를 최우선 구조 대상으로 지정하되, 어울리는 궁합의 재료만 선택해 조리하세요.
3. [완성된 음식 별도 처리] 이미 조리된 음식(예: '엄마가 만든 파프리카감자샐러드')은 세척, 썰기, 볶기 등 생재료 조리 과정을 겪게 하지 마세요. 곁들여 먹기 등 tip 필드로 안내하세요.
4. [재료별 동작 구분] 모든 재료에 "손질하여 볶는다" 식의 동일 표현을 쓰지 말고, 재료별 특성에 맞는 구체적 조리 동작(양파는 썬다, 삼겹살은 먹기 좋게 자른다 등)을 서술하세요.
5. [조사 괄호 절대 금지] "(을/를)", "(이/가)", "(은/는)" 과 같은 괄호형 조사는 절대 출력하지 마세요. 한국어 받침에 맞는 올바른 조사를 작성하세요.
6. [실제 조리 가능성 우선] 맛과 조리 방식이 자연스러운 레시피를 우선하세요.
7. [데이터 정합성] rescueUsed, basicUsed, extraNeeded, tip, steps의 재료 목록을 엄격히 일치시키세요.
```
